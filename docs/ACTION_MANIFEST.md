# Trusted private action manifest (prototype)

`workshop_validator.action_manifest.compile_action_manifest` bridges an exact-PDF, page-by-page `SourceReview` to **pre-authored** browser actions and trusted expected DOM assertions. It does **not** generate actions from PDF text, authenticate Salesforce, or grant PASS.

Use only after a human reviewer has inspected every PDF page and accounted for extraction warnings, images, tables, unnumbered actions and omissions. Supply the exact PDF SHA-256 and reviewed inventory; the reconciliation gate must succeed. Map **every** reconciled ACTION exactly once to an `AuthoredStep` with the correct source page, a private source-region anchor, explicit dependencies, at least one supported click/fill action, and at least one independently checkable DOM assertion. Any unmapped, duplicated, extra, unresolved or non-browser action fails compilation. There is no silent omission or automatic classification of manual-only work. Mark manual/ambiguous steps for review outside this prototype rather than treating them as verified.

The compiler validates allowed action kinds, accessible locators, assertion types, duplicate IDs and the dependency graph. It returns an ordered `ActionManifest` with required `Step` objects and `checkpoint_inputs()` for freezing expected assertions via `CheckpointStore.create_run` **before** executing anything. The private browser runner should take actions from the same approved revision; an executor must never supply replacement expected assertions or declare PASS. The source PDF hash is retained in the in-memory manifest but is **not yet persisted** in the checkpoint store, and this is **not** a trusted signed manifest, private cloud runner, or real-org integration.

All real source text, region anchors, action values, expected assertions, approved manifest, checkpoint database, PDFs, and evidence must remain private. The public tests use synthetic values only. Browser observations are structurally attributed, not cryptographically authenticated. Do not store passwords in authored `fill` values; inject approved secrets only in a separately authorized private runner after credential rotation. Never commit private manifests or upload them as public CI artifacts.

Run synthetic tests with `python -m unittest discover -s tests -p test_action_manifest.py -v`. Follow-up work: bind the exact approved manifest to durable checkpoints, then integrate browser observations into evidence-gated transitions; later add explicit manual-step accounting and bounded HTTP 429 retry/cooldown.
