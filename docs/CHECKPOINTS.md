# Evidence-gated SQLite checkpoints (local prototype)

`workshop_validator/checkpoints.py` composes the existing dependency planner and independent evidence verifier into **transactional local checkpoints**. This is a testable precursor to a durable cloud orchestrator, **not** a deployed worker, a cloud queue, or proof of a Salesforce login.

Create a `CheckpointStore(private_sqlite_path)` and call `create_run(run_id, org_id, steps, trusted_assertions)` once. The store freezes the trusted manifest and assertion specifications. Use `schedule(run_id)` to identify eligible steps. `start_step` atomically moves an eligible `NOT_RUN` step to `RUNNING` and returns an attempt version. Call `finish_step(run_id, step_id, version, context, observations)` to independently evaluate observations against **stored** assertions. Only `verify_step` can grant `PASS`. For a classified gateway or authentication blocker, `block_step` accepts only `ENV_BLOCKED` or `AUTH_BLOCKED`, never `PASS`.

`BEGIN IMMEDIATE` transactions serialize claims and completions across SQLite connections. A stale attempt version, a second claim, a wrong run/org/step context, or a dependent step with an unverified prerequisite is rejected. After reopening the SQLite database, independently verified `PASS` statuses still unlock dependents; blocked branches do not prevent truly independent steps from running (Option A). Raw observed values are not written to checkpoint records; verification metadata contains only evidence IDs and sanitized reasons.

**Security/production limitations:** This prototype stores run/org identifiers and trusted expected assertion values in SQLite, so the database itself must be kept **private** and excluded from Git. SQLite is not a distributed cloud workflow engine; worker heartbeats, leases, crash recovery, durable retry queues, rate-limit cooldowns, audit trails, immutable evidence binding, and authenticated independent collectors remain unimplemented. Collector/verifier identities are only structurally checked, not cryptographically authenticated. Never let an executor edit the database or supply/replace trusted assertions. A `complete` result reflects checkpointed required steps only; it does **not** establish PDF inventory completeness or end-to-end Salesforce validity.

Run the prototype tests with `python3 -m unittest discover -s tests -v`. The next milestone should add bounded, rate-limit-aware retries and stale-worker reconciliation, then replace the local checkpoint backend with a cloud durable store before deploying real workers.
